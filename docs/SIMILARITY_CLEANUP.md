# PC 感知哈希去重

图库顶部“筛选”和“导出导入”之间的双图片放大镜图标进入。打开窗口不自动扫描；选择全部资源或指定分类、全部图片或静态/动图后，点击开始扫描。

- 严格到宽松对应汉明距离 0–16，默认 6。松开滑条重新匹配缓存特征，并清空选择。
- 结果仅为疑似相似，不显示概率，不评价画质，不默认勾选。透明图合成白底，完整图片缩放为 32×32，DCT 排除直流分量，63 个 AC 系数与中位数比较。
- 静态图用 BK 树检索。固定文件路径顺序分组，每个成员直接匹配组内第一张，每张图片只出现一次，避免链式聚合。PC 没有手机端资源 ID，因此使用稳定路径顺序。
- 动图与静态图分别比较；GIF 和可解码的动态 WebP 按播放时间取 8 个采样点，至少 7 个对应点达标。逐帧解码处理局部帧与 disposal；不转换源文件。不同整体播放速度可匹配，循环起点偏移、局部速度变化、短暂差异可能漏检。
- 图片完整展示，复选框在图片外。悬停播放动图，点击进入组内大图预览。显示尺寸、文件大小、分类和动图时长。每页最多 36 张，列数随窗口宽度变化，选择跨页保留。
- 删除必须明确确认，复用图库现有串行删除队列和 StorageService，清理文件、分类、元数据和索引，完成后刷新图库与相似组。删除失败沿用图库通知。
- 扫描和匹配在 QThread 中执行，可取消；关闭窗口先等待取消完成。`data/cache/similarity-v1.db` 独立缓存按绝对路径、文件大小和纳秒修改时间校验。取消保留已完成缓存，可删除缓存后重算；算法变更需升级缓存版本。
- 此功能不参与导入查重、sync_key 或资源包身份计算。宽松阈值下 BK 树仍可能退化；动图逐对匹配，大型动图库首次扫描及匹配可能较慢。Pillow 对部分格式需要完整解码一帧，不同时保留所有帧。

验证：`python -m unittest discover -s tests -p "test_similarity*.py" -v`

测试涵盖静态特征、透明底、亮度变化、分组与穷举对照、时间采样、7/8 边界、缓存与取消、界面交互、动图句柄释放、真实图库入口与多分类删除。所有资源操作使用独立临时目录。
