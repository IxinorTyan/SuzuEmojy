# 自动粘贴回归约束

一次点击依次完成：固定目标窗口、复制图片、按设置隐藏面板、恢复目标前台、确认目标身份和剪贴板内容、发送一次 Ctrl+V。目标消失、切到其他窗口、剪贴板被替换或注入失败时，不继续发送。

Windows 的 Qt 剪贴板通知是异步的。`setMimeData()` 返回后才到达的自身 `dataChanged` 通知，可能正好发生在自动粘贴等待焦点期间。不能直接把所有通知连接到 `cancel()`：这会导致图片已经复制成功、自动粘贴却几乎每次被取消。只有失去剪贴板所有权或系统剪贴板序列号改变，才取消等待中的操作。

Windows 可能拒绝面板隐藏后的普通前台切换。首次切换失败时，临时连接相关窗口的输入队列并重试，随后立即断开。定时检查只等待已固定的目标，不重复抢前台；发送前仍核对目标进程/线程、窗口句柄、当前前台、剪贴板序列和按键状态。

验证：

- `python -B -m unittest discover -s tests -p test_auto_paste.py`：延迟自身通知继续粘贴、外部替换取消、目标切换和失效、修饰键、焦点恢复及失败清理。
- 在交互式 Windows 桌面中设置 `SUZU_TEST_NATIVE_PASTE=1`，再运行 `python -B tests/test_auto_paste_windows.py -v`：两个独立进程实际复制图片并发送 Ctrl+V，接收窗口验证图片和中文/空格文件路径；覆盖源面板显示及隐藏两种方式。测试保留并恢复原 OLE 剪贴板，只允许向临时接收窗口粘贴。此测试不能与使用 offscreen 平台的 Qt 进程合并运行。
